# E2E Test Runner

独立执行端到端测试。生成测试用例，通过双子 agent 并行执行（Maestro 操作 + 日志监控）。

## Steps

### Step 1: 确定保存目标 + 生成测试用例
[experience.md](experience.md)
**先确定保存目标：**
- 用户传入了文档路径 → 读取该文档，找到"测试用例"章节，用例直接写入该文档或者追加
- 用户未传入文档路径 → 保存到 `docs/testcase/e2e-[需求].md`

**然后获取上下文：**
- 用户提供的技术方案文档
- 当前对话中的代码修改记录
- 相关需求文档

基于上下文和代码探索生成测试用例。每个用例必须标注验证方式（UI 可见 / 日志可查 / 两者兼有），无法通过 UI 或日志验证的用例标记为「不可自动化」并说明原因。

格式：

```
## 测试用例

| # | 用例名称 | 操作步骤 | 预期结果 | 验证方式 |
|---|---------|---------|---------|---------|
| 1 | xxx     | 1. xxx  | xxx     | UI + 日志 |
| 2 | xxx     | 1. xxx  | xxx     | UI       |
```

验证方式说明：
- **UI**：通过 `inspect_screen` 检查元素可见性/文本/状态
- **日志**：通过 logcat/idevicesyslog 过滤关键词确认
- **UI + 日志**：两者都要验证
- **不可自动化**：需要人工判断（如视觉样式、动画流畅度），从用例列表中移除或降级为手动用例

生成后使用 `AskUserQuestion` 请用户确认/修改。用户确认后，后续步骤（保存、执行）一气呵成，不再中断询问。

### Step 2: 保存用例

将确认后的用例写入 Step 1 确定的保存目标（原文档的测试用例章节，或新建文件）。不要创建额外的独立文件。

文档中为每个用例预留结果标记位：

```
| # | 用例名称 | 结果 | 备注 |
|---|---------|------|------|
| 1 | xxx     | ⬜   |      |
```

⬜ = 待执行，✅ = 通过，❌ = 失败

### Step 3: 检查环境

**检查 Maestro CLI：**

```bash
maestro --version
```

未安装 → 根据操作系统引导安装，参考 https://maestro.mobile.dev/getting-started

**检查 Maestro MCP：**

```bash
claude mcp list 2>/dev/null | grep -i maestro
```

未添加 → 运行：

```bash
claude mcp add maestro -- maestro mcp
```

两项都通过后**告知用户 Maestro Viewer 链接**，便于实时查看测试执行过程。


### Step 4: 启动子agent，执行测试并验证结果

> ⚠️ **硬性前置**：执行任何用例前，必须先用 Read 工具读取 [经验库](experience.md)，将其中的规则作为约束遵守。未读取就执行 = 违规。

> ⚠️ **确认界面状态是子agent的事情**

#### **子 Agent 1 — Maestro 执行者**（background）：

- 读取 [经验库](experience.md)（**必须用 Read 工具，不能凭记忆**）
- 对每个用例：编写/复用 YAML flow → 通过 Maestro MCP 执行 → inspect_screen 验证
- 遵守经验库中的所有规则
- 新发现的可复用 flow 保存到 `flows/` 目录
- 新发现的教训追加到 `experience.md`
- **逐用例汇报**（根据验证方式）：
   - **UI 用例**：直接判断，输出 `>>> #X 结果: ✅/❌ - 原因`
   - **日志 / UI+日志 用例**：输出 `>>> #X 需要日志验证 - 关键词: "amount,validate,error" - 判断标准: 日志中出现xxx则通过，出现yyy则失败`
- 全部完成后输出汇总表格

#### **子 Agent 2 — 日志监控**（background）：

**被动模式**：启动时根据平台清空日志一次，之后等待主 agent 查询。

- 启动时检测平台并清空日志：
   - Android：`adb logcat -c`
   - iOS 模拟器：`xcrun simctl spawn booted log stream --level error`（后台）
- 收到主 agent 查询时（带**关键词**和**判断标准**），执行日志查询并自行判断结果，只返回 `✅/❌ + 简要原因`
- Android 查询：`adb logcat -d | grep -iE "关键词"`
- iOS 查询：对应日志流过滤

#### **主 agent 协调流程**：

1. 启动两个子 agent（均 background）
2. 收到 `>>> #X 结果: ✅/❌` → 直接记录
3. 收到 `>>> #X 需要日志验证 - 关键词: xxx - 判断标准: yyy` → 向日志 agent 发送「查询 #X，关键词: xxx，判断标准: yyy」→ 记录日志 agent 返回的 `✅/❌ + 原因`
4. 对每个用例重复步骤 2/3
5. 全部完成后，进入 Step 5

### Step 5: 汇总结果

收集两个子 agent 的结果，更新用例文档中的 ⬜ → ✅/❌。

向用户报告：

```
## E2E 测试结果

| # | 用例名称 | 结果 | 备注 |
|---|---------|------|------|
| 1 | xxx     | ✅   |      |
| 2 | xxx     | ❌   | 未找到xxx元素 |

### 新增 flow
- xxx.yaml (如有)
```

**重要：先执行完所有用例再报告，不要遇到失败就停止。**

### Step 6: 修复重测（如需要）

使用 `AskUserQuestion` 询问：

- **全部通过，结束测试**
- **有失败，修改代码后重跑** — 用户修改代码后，判断是否支持热更新（比如是h5、RN、Flutter），支持则直接继续，不支持则重启 app 后回到 Step 4 重新执行全部用例
- **有失败，调整用例** — 修改用例后重跑
- **记录经验** — 将本次发现的模式/教训写入 [经验库](experience.md)
