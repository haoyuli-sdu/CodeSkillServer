# 实体属性提取 Skill
从非结构化或半结构化文本中，识别实体（Entity）及其属性（Attribute），输出为结构化格式。
---

## 工作流程

### Step 1：理解输入
分析用户提供的文本，判断：
- **实体类型**：人物 / 产品 / 事件 / 其他
- **目标用途**：数据库建表 / API 接口定义 

---

### Step 2：提取规则

#### 属性识别优先级
1. **显式属性**：文本中直接出现的键值对（如"价格：199元"）
2. **隐式属性**：从上下文推断（如"3天内发货" → `delivery_days: 3`）
3. **枚举值**：识别有限选项（如"颜色：红/黑/白"）
4. **关联关系**：实体间的关联（如"订单包含多个商品"）

#### 属性元信息（尽量补全）
| 字段 | 说明 |
|------|------|
| `name` | 属性名（snake_case） |
| `label` | 中文标签 |
| `type` | 数据类型（string/int/float/bool/date/enum/array/object） |
| `required` | 是否必填 |
| `example` | 示例值（从原文提取） |
| `constraints` | 约束条件（长度/范围/格式等） |
| `description` | 补充说明 |

---

### Step 3：输出格式

#### Markdown 表格
| 属性名 | 中文标签 | 类型 | 必填 | 示例值 | 说明 |
|--------|----------|------|------|--------|------|

---

### Step 4：质量检查

提取完成后，自检以下项：
- [ ] 是否有遗漏的关键属性？
- [ ] 数据类型是否合理？
- [ ] 枚举值是否完整列出？
- [ ] 必填/选填是否正确判断？
- [ ] 属性名是否符合目标语言命名规范？

---

## 多实体处理

如果文本包含多个实体（如订单+商品+用户），分别提取，并说明实体间关系：

```
实体关系：
- Order (1) ——包含——> (N) OrderItem
- OrderItem (N) ——关联——> (1) Product
- Order (N) ——属于——> (1) User
```

---

## 特殊场景

### 场景：从代码/注释提取
如果输入是代码或注释，提取接口参数、返回值、字段定义，补全类型和说明。

### 场景：从需求文档提取
识别名词作为实体候选，识别"拥有"/"包含"/"记录"等动词确定属性归属。

### 场景：属性冲突/歧义
如果同一属性在文本中有歧义，**列出所有可能的解释**，请用户确认。

---

## 输出原则

1. **忠实原文**：属性名和示例值优先来自原文，不随意发明
2. **显式标注推断**：推断出的属性加注 `[推断]` 标记
3. **保留不确定性**：不确定的类型标注 `unknown`，请用户确认
4. **简洁完整**：每个属性都要有 `name`、`type`、`label`，其他字段尽量补全
